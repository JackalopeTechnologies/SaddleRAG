# VF-S9 timing retrieval without the DirectML sorter

Issue: <https://github.com/JackalopeTechnologies/SaddleRAG/issues/189>

The original question was: “How long must an output phase failure persist before the VF-S9 trips and activates its relay?” The VF-S9 instruction manual says **one second or more**. The answer was vector candidate 5 but fell to combined rank 7 with sorting disabled. The passage itself did not repeat the model name; its title and source filename did.

## Search changes

- Keyword indexing now includes page titles and source filenames alongside passage content. Identical title/filename text is indexed once. Indexed-text version 2 identifies rebuilt indexes. Passage text and Google embeddings are retained.
- A query containing one explicit hyphenated model identifier with a digit prefers eligible candidates whose title or filename contains that exact identifier. This is a general rule, with no VF-S9-specific values. Ordinary hyphenated prose is excluded; multiple model identifiers leave ordering unchanged.
- Source preference applies before selecting the DirectML candidate window and to the final result order in either sorter mode. It preserves fallback candidates and never admits unpublished, filtered-out, or zero-score injected candidates as source matches.
- Results expose `SourceIdentityMatch`. Raw vector, keyword, and sorter scores remain separate. The final score places source matches above ordinary matches while preserving ordering within each group.

Adding source text alone fixed the original wording but failed two new phrasings. Inspection showed that answers from other Toshiba models displaced eligible VF-S9 passages. Source identity preference recovered the correct VF-S9 material for all five phrasings without the sorter.

## Qualification

The comparison uses the actual `SearchTools.SearchDocs` path, Google `embeddinggemma-2:270m`, the stored document vectors, and `mxbai-rerank-base-v1` on DirectML with the installed batch size of 64 and four runtime threads. It includes the original 29 questions, six prior holdouts, and four new VF-S9 phrasings. Reviews require the correct model's source for timing answers; an answer from VF-S11 or VF-AS3 does not count even if it happens to state the same duration.

The first isolated run used temporary keyword indexes in memory. The final comparison used rebuilt source against the actual installed MongoDB indexes and document vectors, with three warmed rounds and alternating sorter order. It called the complete search method inside a separate process; the running service's setting was never toggled. The installed server was independently checked through its normal client endpoint.

| Check | Sorter off | DirectML sorter |
|---|---:|---:|
| Original VF-S9 question, mean of 3 runs | 120 ms | 502 ms |
| Original VF-S9 answer position | 1, 1, 1 | 1, 1, 1 |
| Original 29 questions, mean of 87 searches | 277 ms | 682 ms |
| Original questions with useful answers within five | 29/29 in each round | 29/29 in each round |
| Exact expected passage within five | 26/29 in each round | 24/29 in each round |
| All five VF-S9 phrasings with correct-model timing evidence | 5/5 in each round | 5/5 in each round |
| Six other holdouts with useful answers | 5/6 in each round | 6/6 in each round |

Exact passage and useful answer measures differ because several equivalent documentation pages exist. The missing exact passage for one new VF-S9 phrasing is answered by the PDF version of the same VF-S9 instruction manual; other Toshiba models are not accepted as substitutes. First-round passages are available in the result artifact, along with source identity and raw component scores.

These are local warmed measurements, not guarantees for a first request or every library. The first installed request after restart took 3,768 ms, including 2,720 ms embedding time. Another isolated installed check took 2,918 ms, including 2,065 ms embedding time; the cause of that transient delay was not isolated. Five consecutive live DirectML requests then took 860, 553, 603, 543, and 538 ms, with embedding times of 31, 23, 13, 14, and 15 ms. The final four averaged 559 ms. No latency outlier was excluded from the three measured comparison rounds.

The clean solution rebuild completed with zero warnings/errors. The full suite completed with 2,463 passed, 24 skipped, and zero failures. Skips cover optional native-model fixtures, alternate runtime builds, symbolic-link privileges, and explicit diagnostics. The installed Google model and DirectML sorter are exercised by the comparison separately.

One NSubstitute holdout remains weaker without DirectML: “How do I make NSubstitute ignore every argument when returning a fixed value?” Sorting off does not retrieve the relevant `ReturnsForAnyArgs` or `Arg.Any` explanation within five results. This remains tracked under the same issue and does not justify silently disabling the live sorter.

## Ollama sorter assessment

Ollama 0.40.7 has no native rerank route in its [server source](https://github.com/ollama/ollama/blob/v0.40.7/server/routes.go). Its [reranking support request](https://github.com/ollama/ollama/issues/3368) remains open as checked on 2026-10-21. A chat-model ranking workaround would need separate quality, latency, and memory qualification; it has no demonstrated advantage here. No new sorter model was installed, and no Chinese-developed model was introduced.
